# 錄製:讓使用者示範一次

使用者在 Kav 的 Chrome 裡親手做一次,Kav 錄下「欄位最後的值、按了哪些按鈕、結果是哪一塊」,轉成流程**草稿**。
草稿之後照一般流程走:參數化 → 試跑 → 程式核對 → (建立時)給使用者確認 → 存檔。錄製只取代「你自己猜頁面」這一段。

## 什麼時候用

- 使用者說「我示範給你看」「我做一次給你看」「開始錄」→ 已經同意,直接開錄。
- **你主動提議**(一定要先問,對方同意才開錄——要花對方時間操作):
  - 建立新流程時,同一個問題 `dry_run` 兩次都不過;
  - 修流程時,同一處修兩次還不過。
- 不要用在:需要登入後才能操作的步驟(請使用者先在 Kav 的 Chrome 自己登入好再錄)、付款或下單、要輸入密碼或卡號的頁面。

## 開錄

1. `start_recording(url)` → 把回傳的 `tell_user` 原文告訴使用者。重點:
   - 用**真實的例子**做一次(例:真的查「台中到台北、10/12 下午三點」),之後才能換成別的值;
   - 在**同一個分頁**裡操作(開新分頁、點進 iframe 裡的表單,這次錄製就不能用);
   - 不要輸入密碼、卡號、身分證等個資(一出現就會停止錄製並刪除);
   - 結果出現後,按頁面上方提示列的「**標記結果**」,再點想要的那一塊(整張表或一段文字;↑↓ 可以放大縮小範圍),最後按「**完成**」。
2. 使用者說「好了」或按了「完成」→ `stop_recording(recording_id)`。

## 看 stop 的回傳

| 回傳 | 做法 |
|---|---|
| `state: incomplete` | 告訴使用者 `reason` 的意思(例:開了新分頁、操作到 iframe、網站自訂元件、送出前就輸入了),請他避開後再錄一次,或改由你手寫流程 |
| `draft: null` + `unsupported` | 這種操作形狀錄製還轉不了(例:在欄位裡按 Enter 送出、欄位被網站自動清空、示範中有加入購物車)。照 `hint` 請使用者改做法重錄(例:改按畫面上的查詢鈕),或你手寫 |
| `draft` 有內容 | 往下做 |
| `warnings` | 逐條處理,不能略過(例:`pre` 的點擊要試跑確認能省略、`single_row` 要自己寫 pattern、`pattern_not_specific`) |

## 把草稿變成流程

1. **參數化**:看 `param_candidates`,把每次會換的值改成 `{參數}`,在 `params` 寫 description / example(**就用示範的值**)/ pattern。`from_default: true` 的是使用者沒動、網站預設的值——日期類幾乎一定要參數化,其他照使用者意思決定。
2. 補 `name`、`description`、`domains`、`intents`。
3. 結果:`rows.columns` 若是空的,照網站表頭填(意思不明顯的寫清楚);`rows.pattern` 看 `live_checks.pattern_specific`,false 就改得更專一。
4. **不要刪 `recorded_from`**。它是存檔檢查的依據;刪掉只是跳過檢查,不會讓錯的流程變對。
5. `steps` 草稿:每個 `then` 都是候選,標了 `needs_review` 的要看 `then_candidates` 挑一個「做對了才會出現」的;`next_page` 的 `end` 要試跑翻到最後一頁看截圖再填。寫法見 `references/steps.md`。

## 試跑與存檔(程式會檢查)

1. **用示範的值** `dry_run` 一次:程式會在一個乾淨的瀏覽器環境(沒有示範留下的 cookie、登入)重播,結果必須和使用者標記的一模一樣(`match: true`)。
   - `match: false` + `needs_profile_state`:這個任務要靠示範當下的瀏覽器狀態才重現得了(例:網站記住了使用者選過的地區)。錄製不支援這類任務;告訴使用者,改由你手寫流程並照一般流程驗證。不要改用使用者的瀏覽器重跑來求通過。
   - `widget_value_not_replayable`:某個欄位是網站自訂的選擇元件,直接填值重現不了。
   - 資料本身一直在變(價格、剩餘名額)→ 示範一致永遠對不上,錄製不支援,不要一直請使用者重錄。
2. 有參數的流程:**換一組參數**再 `dry_run` 一次並通過(證明不是背下範例)。
3. 建立新流程:照 SKILL 第 0 節給使用者看結果確認;修流程:修好直接回報,不用再確認。
4. `save_recipe`:缺任何一項證據會被拒絕,照錯誤訊息補。

## 用錄製修流程

流程壞了、你修兩次都不過 → 問使用者要不要示範一次。錄完 `stop_recording(recording_id, compare_to="<流程名>")`,看 `diff`(哪一步改名、多了一步、值或順序不同、結果欄位不同),**只改對不上的地方**,新的錄製 id 寫進 `recorded_from`,照上面重新取得證據後存檔。

## 要跟使用者說清楚的限制

錄製的摘要(使用者做了什麼、標了哪一塊、網址)會交給你,不會自動去掉個資;錄製檔只存在使用者自己的電腦(`~/.kav-fastweb/recordings/`),30 天後刪除。
